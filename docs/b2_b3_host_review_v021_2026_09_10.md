## 1. P2 — the image binary is still not checked

At `host/b2_manifest.py:397`, `_check_frozen_inputs()` hashes the build evidence file
and compares the image path and digest declared in that JSON with the manifest. It then
sets `checks.image = "ok"` at line 406. It never opens the named image binary.

The isolated reproducer starts with an existing fixture image whose actual SHA-256 and
size match both the build evidence and manifest. Qualification succeeds. With the
manifest, build evidence and B2Q evidence unchanged, both of these still verify as
`qualified: true`, `image: ok`:

- Overwrite the binary with different bytes of exactly the same size.
- Delete the binary entirely.

Changing the build evidence file itself is correctly refused. The missing check is the
last link from its declaration to the binary that a later loader would use. The existing
lifecycle tests and the old reproducer use a declared image path with a fabricated hash;
they never create the binary, so their successful baseline cannot demonstrate this link.

Required correction: resolve the actual image path, require an existing file, hash its
bytes, and compare its size and digest with the manifest and build evidence. Add genuine
temporary image bytes to every successful lifecycle fixture; test deletion, truncation
and same-size replacement without changing any manifest or evidence hash. Ensure these
checks apply to every path that claims the image has been verified. This completes the
previous finding; it does not require a firmware build for the tests.

## 2. P2 — the plan and prediction contract is still only partially compared

Sharing `plan_findings()` between pinning and verification is correct. However, the
function at `host/b2_manifest.py:279` still compares a selected subset of fields. The
prediction comparison at lines 330–335 checks the aggregate deltas and fitness hash,
plus each pair's runs, arm order and target. It omits other operational fields.

Each counterexample below starts from a generated valid plan with its complete, valid
sidecar prediction. One logical field or related field group is changed at a time. All
required file hashes are updated. Both initial `pin_plan()` and independent S3
`verify()` accept every row:

| Artifact | Accepted inconsistency |
|---|---|
| Plan | `session = "B1"` instead of B2 |
| Plan | `schema_version = "99.0.0"` |
| Plan | `primary.alpha = 1.0`, or ties described as positive, or the entire primary block removed |
| Plan | `records.per_pair = 1` and `single_session_total = 1`, despite the unchanged 600-evaluation experiment and correct split |
| Prediction | `predicted_primary.sign_test_p = 1.0` and `verdict = "NOT SUPPORTED"`, despite the original deltas and their p = 0.01953125 |
| Prediction | `fitness_sequence_length = 1` |
| Prediction | First pair identifier changed to 99, its `delta_B_minus_A` changed to −999, or its `base_train_fitness` changed to −999, independently |

There is also a missing connection between two independently verified prediction paths.
At lines 500–503, S3 checks the manifest's prediction path/hash, then `plan_findings()`
checks the prediction beside the plan. It does not require them to identify the same
bytes. Pointing only `manifest.plan.prediction_path` to an unrelated file containing `{}`
and updating `manifest.plan.prediction_sha256` preserves `qualified: true`, although the
manifest and plan now pin different prediction digests.

These are contradictions in the document that would be presented for the next ruling.
Rehashing changes the final manifest, so this review does not claim to bypass an existing
ruling bound to its previous hash. Nor does it claim a deployed adjudicator has used a
wrong primary: that adjudicator has not been built. The defect is that the licensed
S2→S3 transition currently certifies these inconsistent operational inputs.

Required correction: derive a complete canonical operational plan and prediction from
the frozen inputs, then compare the full operational structures at pinning and every
verification. Cover the supported schema/version, session, primary statistic/alpha/ties,
record accounting, sequence length and every per-pair result. Explicitly identify the
small set of informational metadata that may differ. `PLAN_NON_OPERATIONAL` is currently
unused; declaring it does not enforce such a comparison. Tie the manifest prediction
reference and the plan sidecar to the same validated bytes and digest. Keep legitimate
file relocation behavior explicit.

Use complete sidecars in all negative fixtures, assert the named reason for refusal,
and exercise both first pinning and re-verification after rehashing. The new reproducer
includes a valid copied plan/prediction baseline. Wrong map and changed prediction runs
are also tested and correctly refused, demonstrating that the checks are being reached.
