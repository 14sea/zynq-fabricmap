## 2. P2 — deadline producer can emit records rejected by the new validator

Locations: `b4/host/b4_deadline.py:43`–`56`; new contract at `b4/host/b4_sim_schema.py:204`–`237`.

`Deadline.record()` samples the clock for elapsed time, then again through `expired()`, and again to set the first expiry.
Those values need not describe one moment. The new validator assumes that their only difference is millisecond rounding.

Direct production-producer reproduction (no record fields fabricated): construct a real `Deadline(60, clock=...)` with
the monotonic sequence **1000.000** (start), **1059.990**, **1060.010**, **1060.010**, then call `record()`.

It returns:

```json
{"seconds":60,"elapsed_s":59.99,"checks":0,"expired":true,"first_expired_at_s":60.01,"clock":"time.monotonic"}
```

`deadline_findings` rejects both the elapsed/expiry relation and the first-expiry upper bound. These are only 20 ms apart:
ordinary scheduling between samples can do this. It is not a backwards clock, an inaccurate injected record, or the
intended ambiguous sub-ms rounding boundary. The producer, not the validator, created the contradiction.

The full `run_batch` reproduction is also kept: complete arms on the same fixed mechanics pair, inject an external
interrupt at the K9 entry, and supply the above monotonic samples to the first real `record()` call during finalisation.
The clock is passed through the normal `run_batch(clock=...)` argument; the actual record method is **not patched**.
The batch returns **incomplete / exit 3**, but:

- **STOPPED.json is absent** because its deadline failed the new pre-write validator;
- `sim_report.json` exists with `STOPPED.json not written` in its stop detail;
- offline verification returns the two deadline findings for the embedded stop record.

Evidence: `probes_results.json:producer_boundary`, `boundary_stopped_batch`; the complete stopped-directory path is saved.
The probe does not demand that an interruption be relabelled as a deadline: its original stop cause should be retained.

Fix criterion: make deadline recording a coherent snapshot of one monotonic sample, including setting the first expiry
from that same sample when first observed; apply the existing published precision consistently. Do not merely widen the
tolerance or stop checking self-consistency. Add a real-producer boundary test and a full stopped-batch persistence
positive requiring STOPPED, report and clean offline verification. Preserve the soft deadline, first stop reason and all
returned observations. This can be fixed locally without altering the model, thresholds, seeds or research policy.
The initial probe used a wrapper only to swap in the clock sequence while calling the unchanged record method. It is kept
as `probes_attempt1*`; the final probe removes that wrapper entirely and uses the public clock injection path, reproducing
the same record and missing STOPPED. This removes any ambiguity about altering the producer in the full-batch check.
