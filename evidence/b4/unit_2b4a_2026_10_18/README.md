**Mutant dry run before the commit.** The battery of 32 mutants (`b4_2b4a_mutants.py`, archived here with the clean-tree run below) was first run on the pre-commit tree. Three mutants survived it and one test was wrong for the right reason, so commit C also carries these test changes: `test_b4_k9.py` gains `test_summarise_by_hand_an_empty_denominator_is_not_assessable_and_never_a_positive_control` (hand pairs: a semantic with no applicable pair → `fraction` null, not assessable, no positive control, so not all seven; an applicable but never covered semantic → 0.0 and no positive control; `ff_init` counted as the other six) and the end-to-end test now asserts every semantic's `positive_control` and `all_seven_positive_controls` on the exposed seed (these kill M13 "ff_init never a positive control" and M14 "an empty denominator recorded as 100 %", which `recompute` alone cannot catch because it recomputes through the same `summarise`); `test_b4_sim.py`'s drift test now asserts the stop's `stage` is `pair 1 end` and its detail names the input — with the checkpoint made a no-op (M22) the drift had still been caught, but by the final working-tree check, so the test passed for the wrong reason. The battery script itself had two defects found in that run: it located the repository by walking up from its own path (an infinite loop at `/` when run from the scratchpad; now from the working directory, refusing outside the repository) and its hermetic copy lacked `host/b1_model.py`, `host/b2_landscape.py`, `host/b2_maps.py` (the imports of the pinned `b2_search.py`), so the four seeds mutants had no green baseline. The B4 suite on the pre-commit tree after these changes: `Ran 218 tests … OK`.
